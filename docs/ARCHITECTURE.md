# Architecture

Guidewise is one Next.js 16 application (TypeScript, App Router) deployed on Vercel in Mumbai (`bom1`), next to its Supabase Postgres database. The pages and the API live in the same codebase.

## The review pipeline (`src/lib/engine/review.ts`)

1. **Redact** (`redact.ts`): emails, phone numbers, Aadhaar, PAN and card numbers are replaced with placeholders before any AI call. A draft marked confidential is never sent to AI at all.
2. **Code checks** (`code.ts`): preferred terms, banned phrases, approved contacts, student results, disclaimers, brand-name spelling, capitals, length, sentence length, inclusive wording, hidden characters, and every figure compared with the Facts Register (subject first, value second; lakh and crore understood).
3. **AI checks** (`ai.ts`): one judgment rule per call; a rule that returns a finding is asked a second time, and disagreement downgrades the finding to a suggestion. Every answer must pass a Zod schema.
4. **AI vision** (`ai.ts` `readCreative`): each creative is read once (cached by image hash) for text OCR missed and for people shown. It never identifies anyone.
5. **Campaign** (`consistency.ts`): prices, figures, dates and promo codes compared across the caption, every creative and every campaign document; every code check runs on each document, and the AI checks read all the documents and the text in each creative in one request per rule (personal data masked first); code finds which source holds each quote and the verifier checks it there.
6. **Verifier** (`verify.ts`): plain code drops any finding whose quoted words, rule or fact does not exist — in the draft, the image (OCR or vision text) or the document it cites.
7. **Fix re-test**: every fix is applied and checked again; a fix that introduces a problem with no automatic fix is withdrawn; locked phrases cannot be removed.
8. **Risk routing**: a fixed rule table sends outcome claims, regulated content, mismatched prices and people shown to compliance; the rest to the brand reviewer.
9. **Approval receipt**: SHA-256 fingerprint of the approved text, Brand Kit version, every finding and how it was resolved, and the approver.

## Round 3 additions

- **Change impact** (`src/lib/impact.ts`): after any fact or rule change, every draft that used it (`factsUsed`: by value, by subject, by named student; or a finding that cites it) is re-checked against the new Brand Kit. An approved piece that now fails is moved back to review with the reason (`drafts.impact`). The result is shown in the Impact panel and logged (`events.action = impact_assessed`).
- **API and MCP** (`src/lib/governance.ts`, `src/lib/apikeys.ts`, `src/app/api/v1/*`, `src/app/api/mcp`): keys are shown once and stored as SHA-256; scopes `brief:read` and `draft:check`; 30 calls a minute per key; every call is audited (`events.action = api_call`). The MCP server uses the official TypeScript SDK (`WebStandardStreamableHTTPServerTransport`, stateless). `get_brief` returns only facts valid today.
- **Campaign review with AI vision**: `drafts.assets` holds up to 4 documents (pasted, uploaded, or read from a live page by `src/lib/webpage.ts`: main content only, with text hidden from readers separated and labelled; http(s) on standard ports, every resolved address and every redirect checked so private and metadata addresses are refused, 8 s, 2 MB); `DraftImage.vision` stores what vision read.

## AI providers (`src/lib/engine/ai.ts`)

Claude, Groq and Gemini are tried in that order, whichever keys are set (the live site: Groq `openai/gpt-oss-120b`, then Groq `openai/gpt-oss-20b`, then Gemini `gemini-3.5-flash-lite`). Groq limits each model separately, so the smaller model takes over text checks while the main one is rate-limited. Images go to Gemini first. Each call has a time cap (12 s for text, 25 s for images); a provider that is rate-limited or slow is rested for 30–60 s so later calls do not wait on it; answers are cached in Postgres (`ai_cache`). With no provider, the code checks and the whole workflow still run, and the app says so.

## Data (`supabase/migrations/001`–`009`)

`kit`, `rules`, `facts`, `drafts`, `findings`, `events`, `versions`, `receipts`, `ai_cache`, `api_keys`. Every table carries a workspace id; each visitor gets a random workspace, so judges never see each other's work. Browsers never receive database credentials — every read and write goes through the API, which enforces roles.

## Features in detail

What each part of the product does, area by area.

| Area | What it does |
| --- | --- |
| Review pipeline | 1 personal data masked → 2 code checks → 3 AI checks, one rule per call, run twice when they find something → 4 AI vision on creatives → 5 code and AI checks on every campaign document and the text in each creative → 6 prices, dates and codes compared across everything → 7 verifier → 8 fixes re-tested → 9 risk routing by a fixed table → approval receipt |
| Code checks | Preferred terms, banned phrases, approved contacts, student results (course and dated consent), results disclaimer (same-language check for Hindi), brand-name spelling, capitals for emphasis, length per content type, sentence length, inclusive wording, invisible characters that could hide a banned phrase, paid-partnership labels (#ad), offers without an end date or T&C, competitor names, vague link text ("click here"), lower-case multi-word hashtags (with a CamelCase fix), stacked "!!" and emoji clutter, and every figure compared with the Facts Register by subject first, value second (lakh and crore understood); an expired fact with a successor points to it ("Use F-12 instead") |
| Image checks | In the browser, with no AI: OCR (self-hosted tesseract.js, sparse-text layout) so every code check runs on the words in the image, with each line's box kept; dominant colours vs the palette (CIELAB colour difference), with where each colour sits; WCAG contrast measured per text line against the background around it; text size estimated from each line's height and flagged below 16px on a 1080-pixel-wide post; alt text; and the Brand Kit logo found by masked cross-correlation at many sizes and proportions (0.85 to 1.15), on grey values and, if that fails, on colour edges, so a recoloured logo is still found and reported as recoloured (colour found vs expected) or stretched (by how much), then checked for minimum size and clear space. Every image finding carries the region it is about, and `ImageInspector` draws them over the image with a text list. Fonts are not identified (see Known issues). Figures are compared across the caption and every creative, and a mismatch is flagged. AI vision then reads stylised text OCR missed and flags people shown for a consent check |
| Verifier | Plain code drops any finding whose quote is not in the draft, image or document it cites, or whose rule or fact does not exist: "no source, no flag" |
| Facts Register | Evidence, owner, valid-from, valid-until and a required disclosure. A figure used before its start date is flagged as embargoed; after its end date, as outdated; for the wrong subject, as a contradiction |
| Brand Kit | Every rule carries test sentences. It starts as advisory and can only be enforced when its own check passes them. **Make a rule from words**: a reviewer types or selects words from a draft and code proposes a term or pattern rule (numbers generalised safely) with test sentences it has already run, to add as advisory. Rules can apply to some content types only. Every change creates a new version. The whole kit exports and imports as one JSON file |
| Bulk check | **Bulk check** (`/bulk`): paste a content calendar (a blank line between posts) or upload a CSV (`text`, and optional `title`, `content_type`, `date`; read in the browser), up to 50 posts. Each gets the review's code checks with AI off (one read of the Brand Kit, seconds for 50 posts, no AI quota spent): verdict, counts by severity, the top findings quoted, the rules broken most often, a results CSV, and **Open as a review** for the full AI review of any post |
| Channel preview | On New review, as you write: the draft as an Instagram caption (cut after about 125 characters, "… more"), a LinkedIn post (about 210 characters or 3 lines), a Facebook ad (125 characters, "See more"), a WhatsApp message (in full, *bold* rendered), an email in an inbox (subject and about 90 characters of preview) or a page's first screen (about 300 characters). The tab follows the content type; the cut is marked, and it warns when a required disclaimer is missing or after the cut or the call to action from the intent is after it, and notes a price or promo code after it. Characters are counted as readers see them (an emoji is one, never split); cut-offs are approximate and vary by device |
| Guide compiler | Paste brand-guide text or upload a PDF or Word file; get proposed rules with test sentences, and warnings about vague or contradictory passages. The manager confirms each one |
| Workflow | Four roles enforced on the server; high-risk drafts need two sign-offs (compliance, then brand) and the receipt names both; time-limited exceptions that only a reviewer can grant and that reopen when they expire; approval re-checks the draft against the Brand Kit in force; each review lists what was checked and what was skipped; accept, edit a fix before accepting, undo an accepted fix (or a whole Accept all) for 10 seconds, dismiss with a reason, reopen; keyboard review (J/K, A, D, ?); each finding says how the team settled the same rule on its other drafts; locked phrases no fix may remove; comments, versions with word-level changes, request changes, audit log; a read-only share link (valid 30 days, revocable by a reviewer) sends an approved record to someone outside the workspace; the review page shows each creative in the image inspector (outlines over the image, with a text list), offers "Make this a rule" on words selected in the draft (reviewers) and in each finding's details, and reads the draft again every 12 s while the tab is visible and nothing is being edited, saying politely what a teammate changed ("Updated: Kavya approved this draft"); **Invite a teammate** (a reviewer or the brand manager) makes a join link to the workspace: 32 random bytes, only the SHA-256 hash stored in an `invite_created` event, valid 7 days, revocable (`invite_revoked`), look-ups rate-limited per address like share links; `/join/[token]` explains and joins only when Join is pressed (`invite_accepted`), then opens the draft |
| Insights and Guideline Health | Rules that fire and get dismissed most, rules two or more people call unclear, and facts that are expired, embargoed or expiring within 60 days. For a rule with dismissals, Guidewise drafts clearer wording and new tests; code re-runs every test and the manager approves |
| Privacy | Emails, phone numbers, Aadhaar, PAN and card numbers are masked before any AI call. A draft marked confidential is never sent to AI |
| Browser extension | "Check with Guidewise" for Chrome (`extension/`, Manifest V3): select a draft in LinkedIn, Gmail, X or any page and get the verdict and cited findings in a popup, each fix one click to copy. It calls the REST API with a `draft:check` key; it reads the page only when its button is clicked (activeTab), can reach no site but Guidewise, and shows server text as text only. Install: [extension/README.md](extension/README.md) |
| Reliability | One AI adapter (Claude → Groq → Groq's smaller model → Gemini, whichever keys exist; Groq serves the live site, and its smaller model, which has its own rate limit, takes over while the main one is limited) with a 12-second cap per call (25 for images), automatic fallback, and a provider that is rate-limited or slow rested for a minute; answers validated with Zod; an answer cache; every API input validated. Without AI, code checks and the whole workflow still run, and the app says so |
